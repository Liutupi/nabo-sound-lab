# 声音挑战赛（四关连玩）

2026-11-10。未发布的源码改动：没有重新编译 ESP32 固件，没有刷机，没有真机验证。

## 为什么做

现有玩具都是单独的小项目，玩两分钟就结束，没有一个“再来一局”的理由。挑战赛把四个已有玩具串成一局约两分钟的游戏，有合计分、音符评级、称号和最高纪录，并放在主菜单第一项：开机后连按两次 OK 就能开始。

## 规则

四关固定顺序，每关 0–100 分，合计 400 分。每关前有 2.6 秒说明卡，关后有 2.4 秒得分卡，OK 可以跳过卡片。

| 关 | 玩法 | 得分 |
|---|---|---|
| 1 吹蜡烛 | 吹灭 6 根蜡烛，限时 12 秒 | 从第一口气到全灭：1.5 秒内 100 分，之后每慢 6.5 秒少 60 分，最低 40 分。没吹完按已灭根数给分，最多 33 分 |
| 2 走钢丝 | 连续出声 160 ms 锁定目标音，之后累计唱满 6 秒走到头，限时 14 秒 | 进度 × 质量。质量按平均偏差计算：0 音分满分，80 音分以上只剩 35% |
| 3 哼歌飞行 | 连续哼 300 ms 自动校准起飞（不用按键），穿 12 道门，3 次机会，轻松难度 | 穿过的门数 ÷ 12 × 100。8 秒内没有哼唱得 0 分 |
| 4 拍手节奏 | 96 BPM，先听 4 拍，再拍 16 拍 | 原拍手节奏得分 ÷ 16 |

合计分对应的音符和称号：340 分以上 5 个音符“金牌音乐人”，260 分以上 4 个“节奏高手”，160 分以上 3 个“稳定发挥”，80 分以上 2 个，其余 1 个；160 分以下的称号是“再练一次”。

按键：OK 开始 / 跳过卡片 / 下一关 / 再来一局；▼ 在关卡中按当前成绩结束本关（环境太吵、麦克风识别不了时用）；双击 ▲ 返回菜单。关卡进行中 OK 不起作用，避免误触结束。

吹气、有无音高的判定和拍手的起音时钟、45 ms 延迟补偿，与单独的吹蜡烛、哼歌飞行、拍手节奏玩具完全相同。第 3、4 关直接调用 `newgames_model.c` 的规则。

## 文件

- `firmware/main/ui/circus_model.c/.h`：纯规则，整数运算，无分配。状态约 150 字节，静态。
- `firmware/main/ui/sc_circus.c/.h`：场景 `circus`，取麦克风输入、发声、画面。
- `prototype/circus-model.js`：与 C 逐步相同的 JS 规则。`prototype/circus.html`：可玩的规则原型，声音输入用按钮和滑杆模拟。
- `tests/circus_host/`：规则单元测试、C/JS 对拍、故意改坏规则的检查、用合成声音驱动真实 UI 的整局测试。
- `main.c`：新增 NVS 键 `circus`（u16，最高合计分）；串口 `status` 在本场景追加 `circus phase=… stage=… scores=… total=… best=…`。

## 兼容性

- **没有改资源包。** 界面文字只用冻结字体里已有的字形，素材只用已有的 NABO 片段和道具。`firmware/assets/soundlab_assets.bin` 未改动，升级只需要写 app。菜单名用“声音挑战赛”而不是“声音马戏团”，因为“马、戏”不在现有字体子集里；改名需要重新生成字体并同时更新 assets。
- **没有改已有 NVS 数据。** `set`、`vol`、`rec` 的格式不变，只新增键 `circus`。旧固件会忽略这个键。
- 主菜单在“玩”分组第一行插入了新入口，默认选中它；原有项目顺序不变，各下移一行。
- 没有改无线对战、麦克风 DSP、变声、渲染器。

## 已验证（仅宿主机）

```sh
python -m pip install numpy Pillow
CC=gcc NABO_UBSAN=1 python tests/circus_host/test_circus.py
```

- 规则单元测试：流程、各关限时、分步与合并步一致、四关计分、跳过、评级边界。
- C 与 JS 两整局 583 个快照逐项相同。
- 4 个故意改坏的规则都被测试拒绝。
- 真实 UI、麦克风分析、混音、渲染器加冻结资源包，用合成的吹气噪声、220 Hz 哼唱和按拍的噪声脉冲打完一整局（得分 100 / 100 / 58 / 100），再跳过一整局；966 帧逐帧检查缺字、文字越界、显示列表容量、增量与整屏逐像素一致；检查最高分只保存一次、低分不覆盖、退出后释放起音回调。
- 原有 CI 宿主测试（交互、音高、变声）在本改动上通过；交互测试因菜单第一行变化改了一处按键步骤。
- 新增源文件用宿主 gcc 以 `-Wall -Wextra -Werror` 检查通过。

## 没有验证

- **没有用 ESP-IDF 编译**，app 体积、分区余量、RISC-V 上的警告都未确认。
- 没有刷机。真实麦克风下的吹气、哼唱、拍手识别，喇叭提示音与麦克风静音窗口的配合，实体按键手感，帧率，空闲堆和最大连续块，10 轮进出，NVS 最高分的保存与重启读取，全部待真机验证。
- 关卡间的提示音在喇叭发声时会暂停麦克风分析；说明卡 2.6 秒后才开始计时，但用 OK 快速跳过卡片时是否影响下一关开头的识别，需要真机确认。
- `tests/duel_host/test_legacy_ui.py` 的菜单路径已加入 `circus`，但该测试需要 TinyCC，本次没有运行。
- 计分的松紧（比如吹蜡烛 1.5 秒满分、走钢丝 80 音分）是按规则估的，需要真人试玩后调整。
